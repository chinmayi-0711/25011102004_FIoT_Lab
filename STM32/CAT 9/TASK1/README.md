## 1. Objective

Configure UART using STM32CubeMX and HAL, establish communication between the STM32 and a PC terminal, and implement character transmission and reception:

- **Transmit a character:** configure the UART for a standard serial configuration and transmit a character repeatedly to the PC terminal.
- **Receive and echo:** modify the code so every character received from the PC is transmitted back to the PC.

UART settings: asynchronous mode, 115200 baud, 8 data bits, no parity, 1 stop bit (8N1), no flow control. The same settings are used in PuTTY / Tera Term.

## 3. Core Logic / Pseudocode / Code Base

**Working Principle:**

`HAL_UART_Init()` (generated by CubeMX in `MX_USART2_UART_Init()`) configures the peripheral. `HAL_UART_Transmit()` sends bytes to the PC, and `HAL_UART_Receive()` waits for bytes from the PC. Echo is simply "receive one byte, transmit the same byte".

**Pseudocode:**

*Part 1 – Transmit a character*

1. Initialise HAL, system clock and USART2.
2. Transmit a character (e.g. `'A'`) with `HAL_UART_Transmit()`.
3. Wait a short interval (`HAL_Delay(500)`) and repeat.

*Part 2 – Receive and echo*

1. Initialise HAL, system clock and USART2.
2. Receive one character with `HAL_UART_Receive(&huart2, &ch, 1, HAL_MAX_DELAY)`.
3. Transmit it back with `HAL_UART_Transmit(&huart2, &ch, 1, HAL_MAX_DELAY)`.
4. Repeat continuously.

**Code Base:**

Uses `HAL_UART_Init()`, `HAL_UART_Transmit()` and `HAL_UART_Receive()` in polling (blocking) mode. The interrupt (`_IT`) and DMA versions are the later and advanced extensions.

## 4. Inference

**Observation:**

The chosen character appeared repeatedly in the PC terminal. In echo mode, every key typed in the terminal was shown back on screen, which confirms that both TX and RX paths work.

**Conclusion:**

A UART link needs matching settings (baud rate, data bits, parity, stop bits) on both ends. Polling-mode HAL calls are enough for basic character transmit/receive and form the base for string-based commands.
